# BLITZ — знания превращаются в навыки

Учебная платформа команды **Ctrl + C**. Пользователь выбирает любую тему и цель, отвечает на уточняющие вопросы и получает персональную карту обучения. Уроки создаются по мере открытия: теория, наглядные схемы, проверка, карточки и объяснения наставника.

**Сайт:** https://blitz-learning-tahir.taarvihma-z.chatgpt.site

## Быстрый запуск

Нужны **Node.js 22.13+**, npm и Git. Не требуется облачная база, Cloudflare-аккаунт или Docker: локальная SQLite/D1 создаётся автоматически.

```sh
git clone https://github.com/BAITC-Hacks/hack-3263a402-ctrl-c.git
cd hack-3263a402-ctrl-c
npm run install:ci
npm run setup
npm run dev
```

Открыть **http://localhost:5173**. `setup` создаёт `.env.local` из примера и применяет локальную схему; повторный запуск сохраняет данные. Зарегистрируйте собственный логин и пароль (пароль от 15 символов). Вход через ChatGPT в локальном режиме — явно тестовая учётная запись `seedy@sites.test`; используйте регистрацию для проверки разных пользователей.

Для генерации заполните `.env.local` и перезапустите сервер:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-6-astra
```

Нужны API-кредиты и доступ к указанной модели; можно задать другую совместимую с Responses API модель. **Без ключа** работают интерфейс, аккаунты и сохранённые материалы; новые курсы и карточки не генерируются. Ключ используется только сервером. `.env.local`, пароли, локальная база, сессии и пользовательские ответы не входят в репозиторий. Генерация отправляет введённые учебные данные в OpenAI.

## Реализованные функции

- Личный кабинет с логином/паролем либо входом через ChatGPT; данные разделены по владельцу.
- Пустая библиотека для нового пользователя; блицы плитками с процентом освоения.
- Три уточняющих вопроса с готовыми вариантами и собственным ответом.
- Гибкая карта: 1–12 тематических этапов, до 10 тем на этап, до 60 тем всего. Число определяется целью, а не шаблоном 3 × 3. Проекты необязательны.
- Урок по запросу: связная теория от основ, структурированные визуализации, подробное объяснение выбранного фрагмента.
- Новые тесты: 10 вопросов с одним правильным ответом; разбор выбранного варианта, ссылки на разделы теории. Сохранённые старые уроки совместимы.
- Самостоятельный ответ, работа над ошибками, отдельное закрепление. Навык подтверждается правильными основными ответами и устранением ошибок, а не открытием страницы.
- Карточки: 12–20 вопросов по теории, ответ по памяти, семантическая проверка пересказа, просмотр объяснения, повторение через 3/7/14/30/60/90 дней. После ошибки или просмотра ответа — через сутки. Дополнительная тренировка до срока не приносит XP.
- Серверный журнал опыта, 30 рангов и отдельные уровни по направлениям. Повтор обычного действия не выдаёт награду снова; общий XP растёт и после уровня 30.
- «Мой прогресс»: плитки блицев, темы раскрываются внутри; ранги, навыки и последние награды. Профиль показывает текущий ранг и шкалу.
- Проекты с критериями, сохранением работы и обратной связью ИИ. Пользовательский код не исполняется.

## Опыт и прогресс

| Действие | XP |
|---|---:|
| Завершить теорию кнопкой перехода к практике | 20 |
| Верный самостоятельный ответ | 30 |
| Верный ответ теста с первой попытки / после ошибки | 10 / 5 |
| Ответить на все вопросы теста | 30 |
| Первые ответы: 80–99% / 100% | дополнительно 30 / 50 |
| Вспомнить карточку впервые / повторить по расписанию | 3 / 5 |
| Исправить первоначальную ошибку отдельным закреплением | 10 |
| Подтвердить все навыки этапа | 100 |
| Малый / крупный проект | 150–300 / 300–600 |

Бонусы 80% и 100% не складываются. Качество теста для бонуса фиксируется по первым ответам. Размер проектной награды определяется сложностью заранее и показан в задании. Намеренная ошибка после первого правильного ответа не даёт награды за исправление. Уникальность `(owner,event_key)` и транзакционная запись защищают от повторного получения XP, в том числе из двух вкладок.

Пороги рангов и титулы: `lib/experience.ts`. Процент: `(XP − начало уровня) / (следующий порог − начало уровня)`. Например, 9884 XP → уровень 17, 68%, следующий порог 10300. Уровни показывают учебный опыт, а не независимую сертификацию знаний. Подтверждённые навыки отображаются отдельно.

## Проверка для жюри

```sh
npm run typecheck
npm test
npm run build
```

Короткий сценарий:

1. Зарегистрировать пользователя A. Убедиться, что «Мои блицы» пусты.
2. Создать блиц, например «Публичные выступления: объяснять идеи коллегам». Ответить на вопросы о начальном опыте, результате и времени.
3. Открыть карту, затем первый урок. Посмотреть теорию, визуализацию и запросить подробное объяснение фрагмента.
4. Завершить теорию и пройти несколько вопросов. Ошибиться, открыть объяснение и закрепление; проверить изменение прогресса и XP.
5. Во вкладке «Карточки» создать набор, ответить по памяти. Повторить ту же карточку: дополнительный XP до срока не начисляется.
6. Открыть профиль и «Мой прогресс». Обновить страницу: данные сохраняются. Войти пользователем B: данные A недоступны.

Генерация обращается к реальному API и может занять несколько минут; она не является локальной заглушкой. Для пятиминутного показа подготовьте один урок в своём демонстрационном аккаунте заранее. Сохранённые курсы не подменяют персональную генерацию для нового пользователя.

HTTP-проверки без платных AI-вызовов: `python3 tests/accounts.py` (при запущенном dev-сервере); `tests/smoke.py` предназначен для старой тестовой Python-учётной записи и создаёт локальные тестовые данные. Для UI/серверного тестирования используйте отдельную локальную базу, не production.

## Технологии и архитектура

React 19, TypeScript, Vinext/Vite, Cloudflare Workers, SQLite/D1, Drizzle, Radix UI, Tailwind, OpenAI Responses API.

- `app/blitz-app.tsx`, `components/blitz/` — интерфейс, библиотека, урок, карточки, прогресс и профиль.
- `app/api/learn/route.ts` — учебные операции, проверка владельца и валидация входных данных.
- `app/api/auth/route.ts`, `lib/identity.ts` — аккаунты, хеши паролей и серверные сессии.
- `lib/theory-prompt.ts`, `lib/assessment-prompt.ts`, `lib/cards-prompt.ts` — промпты автора теории, тестов и карточек.
- `lib/course.ts`, `lib/assessment.ts`, `lib/cards.ts` — проверка структуры генерации и отделение ответов от публичных заданий.
- `lib/experience.ts`, `lib/experience-store.ts` — правила XP и идемпотентный журнал наград.
- `lib/card-service.ts` — карточки и расписание повторений с защитой от одновременных обновлений.
- `db/schema.ts`, `drizzle/` — схема и миграции. Схема изменяется миграциями, не при пользовательском запросе.

Локальные данные: `.wrangler/state/`. Публикация: Sites, манифест `.openai/hosting.json`. Облачные секреты задаются отдельно. `npm run setup` — только локальный bootstrap текущих добавляющих миграций; production получает исходные миграции через Sites. После будущих изменений с ALTER/переносом данных bootstrap специально останавливается, чтобы не применить их повторно.

## Ограничения и внешние зависимости

До 20 блицев и 60 AI-запросов в сутки на владельца. Создание урока использует несколько запросов. Доступность и стоимость зависят от OpenAI. Нет восстановления забытого пароля, отправки писем, внешнего поиска источников или безопасной среды исполнения кода. ИИ может ошибаться в фактах и оценках; проектная проверка — учебная обратная связь. Короткие самостоятельные ответы проверяются по сохранённым допустимым формулировкам; карточки дополнительно допускают семантическую проверку ИИ. Прогресс ранее сохранённых курсов не сбрасывается, структура старого маршрута автоматически не перестраивается.
