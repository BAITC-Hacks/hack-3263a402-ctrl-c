# Перенос BLITZ в другой аккаунт

Это экспорт исходников для создания независимой копии. Он не передаёт владение текущим сайтом и не меняет его.

## Для пользователя
1. Распакуйте архив в обычную локальную папку, например Documents/BLITZ.
2. Войдите в нужный аккаунт Codex/ChatGPT и откройте эту папку как проект.
3. Подключите Sites и OpenAI Developers, если они доступны в новом аккаунте.
4. Отправьте задачу ниже. Для ИИ понадобится собственный ключ API с доступом к gpt-6-astra и достаточным балансом; не вставляйте ключ в чат.

## Задача для нового аккаунта
Прочитай PROJECT_CONTEXT.md, README.md и TRANSFER.md. Это существующий проект BLITZ, который нужно продолжить и развернуть как новый приватный сайт через Sites в текущем аккаунте. Сохрани интерфейс, готовый курс и учебную логику. Создай новый проект Sites и новую базу D1 с привязкой DB, подключи миграции, безопасно настрой новый серверный OPENAI_API_KEY и OPENAI_MODEL=gpt-6-astra через OpenAI Developers. Выполни подходящие проверки и публикацию. Не пытайся обновлять сайт старого аккаунта. Не выдавай скопированный код за перенесённые данные пользователей. Если данных нет, начни с пустой базы и готового курса. Не меняй модель без согласования.

## Что входит
Все файлы сохранённой версии исходников, готовый курс Python, зависимости и lock-файл, интерфейс, серверная логика, схема и миграции D1, тесты, README и краткий контекст проекта.

Только в экспортной копии из .openai/hosting.json удалён project_id старого сайта: Sites выдаст новый при регистрации. Логические привязки DB и r2 сохранены. Оригинал не изменён.

## Что нужно переносить отдельно
- Данные размещённой базы D1: созданные курсы, попытки/прогресс, сданные проекты, беседы. Миграции создают структуру, а не копируют данные. Учебные записи привязаны к идентификатору пользователя: для переноса собственного прогресса требуется подтверждённое сопоставление старого и нового пользователя, сохранение связей между записями и проверка конфликтов ID. Не переписывайте владельцев всех записей массово.
- Ключи API, баланс/доступ к модели и секреты нового сайта настраиваются отдельно.
- Адрес, права доступа и размещение нового сайта создаются отдельно. Старый сайт остаётся у старого владельца.
- История этого чата, остальные чаты/файлы проекта ChatGPT и история Git не включены. PROJECT_CONTEXT.md помогает продолжить разработку, но не заменяет полный архив переписки.

Не включены .env.local, .git, node_modules, dist, локальная тестовая база и служебные файлы аккаунта. Зависимости и сборка воспроизводятся по README.

Официальная документация: https://learn.chatgpt.com/docs/sites
